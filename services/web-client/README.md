# Plotina Web Client

Веб-клиент системы совместного просмотра видео Plotina. Реализует
контракт из [`api-contract.md`](../../api-contract.md).

## Возможности

- создание комнаты с `display_name` и `control_mode`;
- подключение по `invite_code` (код берётся из URL `?invite=...`,
  `/rooms/<code>` или вводится вручную);
- отображение `invite_code`, `invite_link`, роли и режима управления;
- WebSocket-протокол из контракта: `playpause`, `nextVideo`, `seek`,
  `addVideo`, `removeVideo`, `changeQueue`, `setSettings`, `leaveRoom`,
  `sendMessage`, `getState`, `getChatSeq`;
- подтверждения `commandConfirm` с `duplicate`, сохранённым состоянием
  или сообщением; ошибки `error.code` / `error.message`;
- повтор неподтверждённых команд с тем же `commandId` после
  переподключения (включён по умолчанию);
- heartbeat: клиент отвечает `pong` на `pig` и переподключается при
  таймауте;
- версионирование состояния: новая версия заменяет снимок, старая
  игнорируется, одинаковая принимается для коррекции позиции;
- чат с `messageSeq`: сообщения с номерами больше ожидаемого попадают
  в буфер и показываются только после восстановления пропуска;
  `initialMessageSeq` из `sendState` задаёт начало последовательности;
- отправка следующего сообщения только после подтверждения предыдущего;
- периодический запрос `getState` и `getChatSeq` через WebSocket;
- список участников с ролями и признаком подключения;
- демо-режим комнаты без запущенных сервисов (данные и действия локальные);
- неоновый «пушечный» интерфейс: HUD, подсветка, анимации, карточки очереди;
- клавиатура: `Space` — плей/пауза, `←` / `→` — перемотка на 10 секунд;
- кнопки `↺ 10` / `↻ 10` и слайдер-метка прямо над плеером;
- управление встроенным Rutube-плеером через `postMessage`
  (`player:play`, `player:pause`, `player:setCurrentTime`,
  `player:relativelySeek`) — команды параллельно уходят в контракт.

## Требования

- Node.js 20 или новее;
- npm;
- запущенный API Gateway на `http://localhost:8080`
  (нужен только для реальной работы; демо-режим работает без него).

## Запуск

Из `services/web-client/`:

```bash
npm install
cp .env.example .env
npm run dev
```

Приложение будет доступно по адресу `http://localhost:5173`.

REST-запросы идут на `/api/*` и проксируются Vite на Gateway;
WebSocket — на `/ws`.

## Демо без сервисов

Если нужно просто посмотреть, как выглядит комната, Gateway поднимать
не обязательно:

```bash
cd services/web-client
npm run dev
```

Затем открой `http://localhost:5173/?demo=1` или нажми
**ДЕМО-РЕЙС БЕЗ СЕРВИСОВ** на стартовой странице.

В демо уже есть очередь, участники, чат и включённое видео. Кнопки,
перестановка очереди и отправка сообщений работают локально и ничего
не отправляют в сервисы. Выход возвращает на стартовую страницу.

## Управление плеером

Клавиши работают, когда фокус не находится в поле ввода:

- `Space` — `playpause`;
- `←` — минус 10 секунд;
- `→` — плюс 10 секунд;
- `Ctrl + Enter` в чате — отправить сообщение.

Команды идут в Gateway по контракту, а в Rutube iframe дополнительно
отправляется `postMessage`. Браузер изолирует iframe, но у Rutube есть
внутренний API outside-events, поэтому плеер действительно реагирует на
кнопки и клавиши. Если браузер заблокирует автозапуск, первое включение
звука может потребовать клика по самому плееру.

## Переменные окружения

- `VITE_API_BASE_URL` — базовый REST URL, по умолчанию `/api`;
- `VITE_WS_URL` — полный WebSocket URL; если не задан,
  используется `/ws` текущего origin;
- `VITE_RETRY_PENDING_COMMANDS` — повтор команд с тем же `commandId`;
  по умолчанию включён, выключить можно значением `false`;
- `VITE_HEARTBEAT_TIMEOUT_MS` — максимальное ожидание `pig`,
  по умолчанию `20000`;
- `VITE_STATE_SYNC_INTERVAL_MS` — период запросов `getState` и
  `getChatSeq`, по умолчанию `10000`.

## Ограничения

1. REST-ответ `invite_link` от Room Service указывает на
   `http://localhost:3000/rooms/<code>`. Клиент показывает и
   копирует его как есть; для входа надёжнее использовать
   `invite_code`.
2. История чата до подключения и за время отключения не загружается —
   после `sendState` с `initialMessageSeq` начинается новая
   последовательность.
3. В контракте нет endpoint'а для получения пропущенных сообщений:
   клиент буферизует сообщения с будущими `messageSeq` и ждёт, пока
   пропуск будет разослан Gateway.
4. Rutube управляется через внутренние `postMessage`-события
   (`player:play`, `player:pause`, `player:setCurrentTime`,
   `player:relativelySeek`), найденные в его embed-бандле. Это не
   публичный API: если Rutube изменит имена событий, серверное
   состояние и HUD продолжат работать, но сам iframe может
   перестать реагировать. Если фокус находится внутри iframe,
   браузер не отдаёт клавиши родительской странице — в этом
   случае используйте кнопки на странице.
5. Восстановление прежней сессии по сохранённому токену не
   реализовано: для этого нужен отдельный endpoint Gateway.
