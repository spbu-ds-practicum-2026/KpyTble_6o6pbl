# Виджет чата Plotina

Компактный чат для будущего встраивания в страницу комнаты. HTML, CSS и JavaScript
без frontend-сборки, npm, CDN, внешних шрифтов или библиотек. CSS компонента
изолирован через Shadow DOM и не меняет оформление родительской страницы.

## Посмотреть сейчас, без остальных сервисов

Из `services/chat-service`:

```bash
go run ./cmd/chat-web
```

Открыть `http://127.0.0.1:8099`. Сайт запускается отдельно от Chat API и не требует
PostgreSQL, токена или Room Service. По умолчанию включён явно обозначенный
деморежим: несколько примерных сообщений и отправка от имени «Вы». Сообщения
существуют только в памяти страницы. Другие вкладки их не получают.

Порт можно изменить через `CHAT_WEB_ADDR`. Альтернатива при установленном Docker:

```bash
docker compose --profile web up -d --build chat-web
```

При запущенном HTTP-сервисе тот же сайт доступен на `http://127.0.0.1:6767/chat/`.
Основной API при этом не меняется. Отдельная команда chat-web нужна для быстрого
просмотра интерфейса без backend-зависимостей.

## Что есть в интерфейсе

- Небольшое окно 410 × 570 px в демонстрационной странице; на узком экране
  сжимается по ширине контейнера.
- Автор, время, текст и цветной аватар с первой буквой имени.
- Отправка кнопкой или Enter; Shift+Enter добавляет перенос строки.
- Новые сообщения снизу. Если пользователь прокрутил вверх, позиция сохраняется
  и появляется кнопка перехода к новым сообщениям.
- Кнопка «Стикеры» — заглушка с уведомлением. Изображения пока не отправляются.
- Настройки подключения, индикатор состояния, ошибки и отдельное отображение
  сообщения, ожидающего подтверждения.
- В DOM хранятся последние 300 отображённых сообщений. История из БД не загружается.
- Текст и имена вставляются через textContent, не как HTML.

## Подключение к Gateway

Нажать кнопку настроек в заголовке, указать WebSocket URL и токен участника.
При подключении демолента очищается; новые сообщения приходят только от Gateway.
Сайт не обращается к Chat DB или Room Service напрямую.

Используется последний согласованный контракт:

```text
→ getState + token
← sendState + initialMessageSeq + state
→ sendMessage + commandId + token + payload.text
← commandConfirm + commandId + duplicate + message
← sendMessage + message
→ getChatSeq + token (периодически, без commandId)
← commandConfirm + messageSeq
← pig + pigId
→ pong + pigId
```

Временные токены не сохраняются в localStorage, sessionStorage, URL или логах.
Поле токена очищается после подключения. Gateway должен разрешать Origin
страницы (например, http://127.0.0.1:8099). Если сайт открыт по HTTPS, для
Gateway нужен wss://. Истечение/отзыв токена обрабатывает сервер.

Клиент ждёт initialMessageSeq; до него отправка выключена. События буферизуются
и отображаются по возрастанию messageSeq, повторы игнорируются. Следующее своё
сообщение отправляется после подтверждения и обработки предыдущего. При потере
ответа отправка повторяется с тем же commandId и текстом. При переподключении
принимается новый начальный номер; старая история повторно не показывается.

Если обнаружен пропуск, следующие сообщения остаются в буфере и отображается
уведомление. Автоматическое восстановление пропусков пока невозможно: endpoint
для него ещё не согласован. Виджет не подменяет эту функцию загрузкой истории
или показом сообщений в неверном порядке.

### Откуда берётся имя автора

В message есть participant_id, но в согласованном state.participants пока нет
гарантированного идентификатора для связи с display_name. Если Gateway передаёт
participant_id (или id) вместе с именем, виджет использует его. Иначе показывает
полный participant_id, а не угадывает имя по позиции в массиве. Имя «Вы»
определяется после подтверждения собственной отправки.

Родительский интерфейс может явно передать словарь имён через setAuthors.
Расширение state идентификаторами участников нужно согласовать с командой.

## Встраивание

Разместить файлы web на том же сайте и подключить модуль:

```html
<script type="module" src="/chat/chat-widget.js"></script>
<aside style="width: 380px; max-width: 100%;">
  <plotina-chat style="--chat-height: 540px;"></plotina-chat>
</aside>
```

Компонент сам не включает деморежим. Его можно настроить из кода страницы:

```js
await customElements.whenDefined("plotina-chat");
const chat = document.querySelector("plotina-chat");

// Для макета:
chat.useDemo();

// Для настоящей комнаты (token получен при входе):
// chat.connect(gatewayURL, token, {"participant-id": "Имя участника"});

// Если имена появились позже:
// chat.setAuthors({"participant-id": "Новое имя"});
```

Готовность WebSocket, сообщения и очередность реализованы в chat-client.js,
внешний вид и ввод — в chat-widget.js / chat-widget.css. Обёртка отдельной
страницы — index.html / preview.css / preview.js. Текстовые команды, стикеры
и цензура не реализуются в браузере: их исполнение и проверка прав — backend.

## Проверка интерфейса

Go-тесты проверяют выдачу встроенных статических файлов и доступность `/chat/`.
Дополнительный скрипт `scripts/check_chat_web.py` проверяет интерфейс в настоящем
Chromium: ввод, переносы, авторов, безопасность отображения текста, автопрокрутку,
порядок событий и переподключение. WebSocket Gateway в нём подменяется в браузере,
поэтому это не тест настоящего Gateway.

При установленном Python Playwright и Chromium, на запущенном chat-web:

```bash
python3 scripts/check_chat_web.py --url http://127.0.0.1:8099
```

Playwright нужен только для дополнительной проверки интерфейса; сайт и сервис
работают без него. Параметр `--screenshots .local/screenshots` сохраняет снимки
широкого и узкого экрана для визуальной проверки.
